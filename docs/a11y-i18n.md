# Accessibility and internationalisation

Applies to `zunia-extension`, `zunia-dashboard`, `zunia-mobile`, and `zunia-website`.

## Requirements (WCAG 2.2 AA)

- Contrast: both light and dark themes meet 4.5:1 for body text, 3:1 for large text.
  Enforce with the existing `zunia-ui` contrast check in CI.
- Screen readers: amounts and addresses expose accessible names (`aria-label` with
  spoken form, e.g. "1.5 ATOM" and chunked address "cosmos 1abc ...").
- Addresses: render in monospace with visual chunking (4-character groups); never
  truncate below 8+8 in signing prompts.
- RTL: all user-facing strings go through the i18n layer; layout uses logical
  properties (`margin-inline`, `padding-inline`) rather than left/right.
- Focus: visible focus rings on every interactive control; no `outline: none`
  without a replacement.

## String extraction

- Extension / dashboard: `i18next` (or the repo's existing i18n helper) with
  English as source of truth under `locales/en/`.
- Mobile: Flutter `intl` / ARB files under `lib/l10n/`.
- Never concatenate translated fragments; use ICU placeholders.

## Locale-aware formatting

- Amounts: `Intl.NumberFormat` / `NumberFormat` with the chain's decimals.
- Dates: `Intl.DateTimeFormat` with the user's locale; always include timezone
  in activity detail views.
- Do not invent currency symbols for non-fiat denoms; show the denom string.

- [ ] RTL smoke on Arabic locale
- [ ] VoiceOver / TalkBack pass on seed reveal and amount entry
